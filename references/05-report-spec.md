# 报告规范

交付物是**单文件 HTML**，离线可开，含浅色/深色切换。理由：这类报告会被反复翻看、转发给合伙人、几个月后回头复核，PDF 改不动、Markdown 看不出层次。

## 章节骨架

| 章 | 标题 | 必须包含 |
|---|---|---|
| 头部 | 摘要条 | 市场、周期、候选数、结论（主推 / 备选 / 否决） |
| 01 | 定义：这次的「符合条件」指什么 | 9 条硬筛全文 + 阻塞项（收款等） |
| 02 | 候选池 | 检索轮次、去重后数量、全表（含淘汰标记） |
| 03–08 | 逐轮验证 | 每轮：方法 / 结果 / 否决了谁 / 为什么 |
| 09 | 收敛 | 最终结论表、单位经济、敏感度、广告起步线 |
| 10 | 执行 | 周计划、Kill 条件、免费与付费如何同步 |
| 11 | 边界 | 未取得项、口径陷阱、复跑路径、采集日志 |

## 标注体系

全文每个判断都挂一个来源等级 chip：

| chip | 含义 | 用法 |
|---|---|---|
| A 现场读取 | 本次在浏览器里读到的 | 附采集时间与 URL |
| B 官方原文 | 法规、平台帮助中心 | 附链接 |
| C 第三方估算 | 平台估算值 | 必须注明「估算」 |
| D 推断 | 逻辑推理 | 必须写明推理链 |
| X 未取得 | 明确没拿到的 | 单列一章，不进结论 |

## 表格规范

- 每张表上方给一行口径说明：采集时间（精确到分钟）、地区、周期、指标定义
- 金额统一 `$`，大额用「万」并保留两位小数（`$580.94 万`）
- 区间写成 `$2.20–5.60`，不要写成「约 3 美元」
- 成本表用底色区分：变动成本合计一行、贡献毛利一行
- 敏感度表最后一列写「能不能跑广告」，不要只给数字

## 语气规范

- 结论先行，理由在后
- 被推翻的结论保留，标注「被什么数据推翻」——删掉会让人重复踩坑
- 不用「大概」「应该是」「仅供参考」
- 不确定就写「未取得」，并写清去哪拿、找谁拿
- 对不利结论不要软化。写「这个品在独立站没有立足点」，不写「可能需要进一步观察」

## 结构要求

- 顶部固定导航，可跳到任一章
- 章节 id 统一 `s1`…`s11`，便于外部链接定位
- 关键结论用 callout 块（info / warn / danger / todo 四类），不要用加粗段落代替
- 页脚写明采集时间范围与全部数据源
